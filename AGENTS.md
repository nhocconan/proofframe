# ProofFrame V3 project instructions

Read the engineering handoff and implementation specification before editing. This package is a research/specification handoff plus a small original contract/policy seed, not a finished application.

Never replace an existing project instruction file blindly. Reconcile these instructions with the target repository. Preserve user work and avoid unrelated changes.

Truth boundaries are mandatory: approved intent, observations, hypotheses, policy and repairs are separate. Output-version changes must not rewrite approved intent. Missing/error/unsupported checks cannot PASS. The verifier may recommend but cannot publish. Do not leak producer claims or seeded labels into perception prompts.

Synthetic fixtures are explicitly synthetic; real integrations need real execution evidence. Do not call contract tests a perception benchmark. Do not claim savings, reliability or SOTA without an appropriate comparison.

Secrets stay in environment/authorized stores. Paid execution requires configured bounds. No host administration, arbitrary shell repairs, unapproved publication, private footage in Git, or silent provider fallback. Use a bounded workflow rather than an unbounded multi-agent conversation.

Use the existing project's compatible conventions. Keep the typed domain independent from SDKs. Add tested provider capabilities, not speculative universal wrappers. Use one implementation behind CLI, API and UI.

The initial seed supports conservative same-target repair authorization and constant positive-speed timeline mapping only. Extend these with tests before exposing upstream source edits, nested timelines, nonlinear retimes, transitions or new automation permissions.

Run tests after changes; record actual commands and failures in docs/BUILD_STATUS.md. Keep source/license/provenance records current. The next task is an actual video-to-evidence vertical slice, not another design document.

Agent working artifacts belong in gitignored `private/`; shipped operational guidance belongs in `docs/`.

## Verification rules

1. Validate provider JSON locally against the requested schema before accepting it. Unknown verdicts, severities, non-finite numbers and unresolved entity correspondence must never produce PASS. Enforcement: adapter, continuity and artifact-scan regression tests in the required pytest CI gate.
2. Score distinct defect claims with one-to-one matching. Human adjudication takes precedence over automatic overlap and is scoped to its baseline; unresolved findings cannot establish precision. Entity identity alone does not establish a shared root cause. Enforcement: evaluation regression tests in the required pytest CI gate.
